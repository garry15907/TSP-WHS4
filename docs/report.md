## 1. 요구사항 분석

멘토님께서 제공하신 과제 PDF에 있는 최소 요구사항을 기준으로 다음 기능을 반드시 구현 대상으로 잡았습니다.

- 회원가입과 로그인
- 상품 등록, 조회, 상세보기, 검색
- 플랫폼 사용자 간 소통
- 악성 사용자와 상품 차단
- 사용자 간 송금
- 관리자에 의한 전체 관리

비기능 요구사항은 다음과 같이 정리했습니다.

- 보안: 인증, 세션, 입력 검증, SQL 인젝션/XSS/CSRF 방어
- 가용성: 과도한 요청 제한, 단순한 로컬 실행 구조
- 유지보수성: 역할별 코드 분리, 보고서와 체크리스트 문서화

## 1.1 최소 요구사항 대응표

- 회원가입/로그인: 구현 완료
- 상품 등록/조회/상세/검색: 구현 완료

- 악성 유저/상품 차단: 신고 누적 기반 자동 차단 및 관리자 수동 차단 구현 완료

## 2. 시스템 설계

### 2.1 아키텍처

- 서버: Express
- 템플릿: EJS
- 데이터 저장소: Node 24 내장 `node:sqlite`
- 실시간 통신: Socket.IO
- 인증: 세션 기반

### 2.2 데이터베이스 설계

- `users`: 사용자 계정, 역할, 상태, 잔액
- `products`: 상품 정보, 판매자, 상태
- `reports`: 신고 기록, 신고 대상, 신고 사유
- `global_messages`: 전체 채팅
- `direct_messages`: 1:1 채팅
- `transfers`: 사용자 간 송금 기록

### 2.3 권한 설계

- 일반 사용자: 상품/대화/송금/신고
- 관리자: 모든 사용자/상품/신고 현황 확인 및 상태 변경

## 4. 확인한 보안 약점과 변경 사항

### 4.1 평문 비밀번호 저장 위험

- 약점: 초기 설계에서 비밀번호를 그대로 저장하면 유출 시 즉시 계정 탈취가 가능했습니다.
- 변경: `bcryptjs` 해시 저장으로 변경했습니다.

### 4.2 CSRF 위험

- 약점: 세션 기반 인증만 사용하면 외부 사이트가 사용자의 브라우저를 통해 상태 변경 요청을 보낼 수 있었습니다.
- 변경: `csrf-sync`를 적용해 모든 상태 변경 폼 요청에 토큰 검증을 넣었습니다.

### 4.3 SQL 인젝션 위험

- 약점: 문자열 결합 기반 쿼리는 입력값 조작에 취약했습니다.
- 변경: SQLite prepared statement만 사용하도록 구현했습니다.

### 4.4 XSS 위험

- 약점: 상품 설명, 소개글, 채팅 메시지를 그대로 렌더링하면 스크립트 주입이 가능했습니다.
- 변경: EJS escape 출력과 서버측 길이/형식 검증을 사용했습니다.

### 4.5 과도한 인증 시도

- 약점: 로그인/회원가입 엔드포인트는 브루트포스 대상이 되기 쉬웠습니다.
- 변경: `express-rate-limit`로 인증 및 일반 요청 모두 제한했습니다.

### 4.6 파일 업로드 취약점

- 약점: 이미지 업로드는 악성 파일 업로드, MIME 위장, 저장 경로 문제를 수반했습니다.
- 변경: 첫 구현에서는 이미지 URL만 허용해 공격면을 줄였습니다.

### 4.7 권한 우회

- 약점: 상품 상태 변경, 관리자 기능, 자기 자신 신고/송금 등은 권한 검증이 없으면 악용될 수 있었습니다.
- 변경: 로그인/관리자 미들웨어와 소유자 검증, 자기 자신 대상 금지 로직을 넣었습니다.

## 4.8 보안 변경 요약표

| 항목 | 위험 | 변경 내용 |

## 6. 유지보수 계획

- 이미지 업로드가 필요하면 업로드 전용 스토리지와 파일 검증 체계를 추가하는 방향으로 계획했습니다.
